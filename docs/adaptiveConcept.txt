Step 1 — Decide What You’re Actually Tracking

You do not want to store entire trips for adaptation logic.

You want to store patterns.

Think:

Instead of:

“Winnipeg → Toronto, June 12, 3 people…”

You store:

{
  hotelTier: "budget",
  foodBudgetPerDay: 85,
  gasBufferPercent: 10,
  averageTripLengthDays: 5.4,
  prefersScenic: true,
  detourToleranceKm: 18,
  fuelStopsAddedManually: 3,
  typicalBudgetRange: 1200-1800
}

You’re tracking behavior, not itinerary.

Step 2 — Where To Store It

You have 3 realistic options:

A) LocalStorage (Device-Based)

Stored in browser

Zero backend required

Fully private

Lost if user clears browser

Perfect for:
MVP
Privacy-first positioning
Low complexity

B) Account-Based (Server DB)

Persists across devices

Enables deeper adaptation

Requires auth layer

More complexity.
But stronger long-term retention.

C) Hybrid (My Recommendation for You)

Start with:

LocalStorage profile

Optional export/import profile JSON

Later upgrade to account sync

This keeps it indie-friendly but scalable.

Step 3 — How The Engine Learns

This is the key part.

You don’t adapt instantly.

You use smoothing.

Example:

User chooses:

Budget hotels 3 trips in a row

You track counts:

hotelChoiceCounts: {
  budget: 3,
  moderate: 0,
  premium: 0
}

When one tier dominates:

That becomes the new default.

Not on first tweak.
Not on second.
After consistent pattern.

Step 4 — How You Avoid Being Creepy

Always surface it.

Instead of silently adjusting:

Show:

Based on your last 3 trips, starting with Budget Hotels.

That builds trust.

If you don’t surface it, it feels manipulative.

Step 5 — What NOT To Do

Do not:

Track every micro adjustment

Build an ML model

Overcomplicate scoring

You don’t need machine learning.

You need:

Weighted averages + simple pattern counters.

That’s it.

Step 6 — Architecture Sketch

Create:

userProfile.ts

export interface UserTripStyle {
  avgFoodPerDay: number;
  avgHotelTier: "budget" | "moderate" | "premium";
  avgTripLength: number;
  scenicPreferenceScore: number;
  detourToleranceKm: number;
}

Update profile after each “Locked In” event.

Recalculate rolling averages.

Store to localStorage.

Load at app start.

Apply as baseline overrides before Estimate Mode runs.

Clean.
Deterministic.
Predictable.
